# v1 実装計画

## 方針

関心テーマを起点にRSS / Atomを収集・保存する。
Web Searchはv1から除外する。LLM、通知、ダイジェスト、フィードバック、OpenSearch構築も後続とする。
旧RSS → GitHub Discussion計画はこの計画に置き換える。旧文書はGit履歴に残る。

## 1. 開発基盤の刷新（今回の範囲）

- README・AGENTS・Copilot指示を新構想に合わせる。
- .codex、.github、.vscode、mise、共通編集設定を見直す。
- 旧計画を削除し、設計・データモデル・開発・運用方針を整理する。
- 認証情報なしのリポジトリ検証をCIに接続する。

アプリ実装やデプロイの完了は、この変更の受け入れ条件に含めない。

## 2. データ契約と技術選定の確定

- テーマ・情報源のYAMLスキーマと多対多の参照を定義する。
- RustとCDKの採用理由、依存・ランタイムバージョンを確定する。
- Document・Discovery・テーマ関連の具体的なスキーマとID計算を決める。
- S3レイアウト、索引、writer競合、manifest公開、中断復旧を確定する。

受け入れ条件: 日またぎ重複、記事更新、複数テーマ、保存中断を例で説明でき、未確定の整合性保証がない。

## 3. ローカルでの縦切り

- fixtureから解析・正規化・ローカル保存まで実装する。
- テーマ指定、設定検証、dry-run、Rawのreplayを提供する。
- 設定・モデル・正規化と入出力アダプターを分離する。

受け入れ条件: AWSや外部APIなしで出力契約、再実行、記事更新、複数テーマ関連を検証できる。

## 4. RSS / Atom の実取得

- タイムアウト、サイズ上限、バックオフ、有限のリトライ、並列数制限を実装する。
- 情報源を共有して取得し、取得失敗・解析失敗を分離して記録する。
- RSS 2.0 / Atom、日付欠落、非UTF-8、特殊エンティティに対応する。

受け入れ条件: 一つの情報源の失敗で他を止めず、原因と成功分を追跡できる。

## 5. AWS への接続

- 同じ保存契約のS3アダプターを実装する。
- 単一Lambda、Scheduler、最小権限IAM、ログ保持・監視をCDKで定義する。
- 自動テストに認証情報を要求せず、CDK synthをCIに追加する。
- デプロイ方法、認証、初回準備と復旧手順を検証して文書化する。

受け入れ条件: AWS上で定期収集し、再試行・競合・部分失敗に対する設計どおりの挙動を確認できる。

## 6. v1 の完了確認

- READMEの手順でローカル環境を再現できる。
- RSS / AtomのRaw・Document・Discovery・テーマ関連を出力できる。
- 同じ記事を日付・テーマ・情報源をまたいで処理しても意図しない重複がない。
- 更新と新しい発見が失われず、保存途中の失敗から復旧できる。
- Rawからネットワークなしで再処理できる。
- CLIとLambdaで同じ正規化結果を得る。
- format・lint・test・IaC検証がCIで実行される。
- 検証結果、既知制約、次の作業を報告する。
